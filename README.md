# Oxide

Oxide — Windows-first медиаплеер для видео и аудио на Rust, Slint и libmpv. Цель
проекта — надёжное локальное воспроизведение, управление с клавиатуры и
собственная дизайн-система, вдохновлённая принципами Raycast, без копирования его
бренда и закрытых ассетов.

> Проект находится на ранней стадии разработки. Базовое воспроизведение работает,
> но упаковка зависимостей, новый рендеринг и полный UI ещё не завершены.

## Реализовано

- открытие локального видео и аудио;
- play, pause, stop и перемотка;
- громкость, mute, скорость и повтор файла;
- смешанный плейлист видео и аудио из папки в естественном порядке;
- отдельный адаптивный аудиорежим;
- распространённые lossless-форматы (FLAC, ALAC/M4A, WAV/AIFF, APE, WavPack,
  TTA) и безопасные gapless-переходы между совместимыми треками;
- аудиотеги и встроенные обложки;
- выбор аудио- и субтитровых дорожек, загрузка внешних субтитров;
- таймер и базовые свойства медиа;
- полноэкранный режим и горячие клавиши;
- передача событий и ошибок libmpv в UI.
- экспериментальная контекстная конвертация через отдельный процесс FFmpeg:
  видео в MP4/H.264, MP4/H.265 и WebM, аудио в MP3, M4A/AAC, FLAC, WAV и Opus,
  а также уменьшение размера и remux без перекодирования.

## Требования

- Windows 10 или новее;
- стабильный Rust toolchain;
- совместимая библиотека libmpv (`mpv-2.dll` во время запуска);
- FFmpeg в `PATH`, рядом с `oxide.exe`, в подпапке `tools` или по пути из
  `OXIDE_FFMPEG` — только для конвертации;
- рабочая C/C++ link-среда для выбранного Rust target.

Поставка libmpv вместе с приложением пока не автоматизирована. Это обязательная
задача перед первым публичным релизом.

## Сборка

```powershell
cargo build
cargo run
```

Проверки проекта:

```powershell
cargo fmt --all -- --check
cargo clippy --all-targets --all-features -- -D warnings
cargo test --all-targets --all-features
cargo test --locked -p libmpv --lib ownership_tests
```

Для `libmpv` используется локальное исправление закреплённого исходного кода
в `vendor/libmpv`: освобождение контекста при ошибке initializer и строковых
буферов при невалидном UTF-8. Происхождение и отличия описаны в
[vendor/libmpv/OXIDE_PATCH.md](vendor/libmpv/OXIDE_PATCH.md).
Нативная DLL не менялась. Проверки `ownership_tests` используют её без окна,
загрузки медиа и вывода звука; общий набор тестов Oxide их автоматически не запускает.

Проверки `converter::lifecycle_tests` входят в общий набор: они запускают копии
тестового executable вместо FFmpeg, проверяют зависание, отмену, ошибки, panic и
очистку процессов/временных файлов, без UI и реальных медиа. `storage::tests`
проверяют повреждение, ошибки записи, резервные копии, аварийный выход и конфликты
между отдельными процессами в собственных временных каталогах. Два `ignored`-теста
`helper_child` в этих модулях — служебные точки входа subprocess fixtures;
остальные тесты запускают их явно. Отдельно запускать `--ignored` не требуется.

## Хранение настроек и истории

С версии `0.8.0-alpha.10` файлы `settings.txt` и `playback-state.txt` сохраняются
через общий транзакционный слой. На Windows они по-прежнему находятся в
`%LOCALAPPDATA%\Oxide` (с запасным вариантом `%APPDATA%\Oxide`). Существующие файлы
читаются без ручного переноса. Новые записи получают заголовок версии хранилища,
длину и контрольную сумму FNV-1a; это обнаружение случайного повреждения, не
криптографическая подпись. Старые файлы без контрольной суммы читаются по прежним
правилам схемы. Старые сборки плеера новый заголовок не понимают.

Запись выполняется во временный файл в той же папке, с `sync_all` перед заменой
основного файла. Рядом хранится одна `.bak` — предыдущая корректная версия;
при первом сохранении копия содержит новые данные. Если основной файл повреждён
или отсутствует, плеер загружает корректную копию и сообщает об этом. Основной
файл восстанавливается при следующем сохранении. Копия не обязательно содержит
самые последние изменения. Если ни один вариант не читается или формат слишком
новый, файлы остаются нетронутыми: плеер работает с временными значениями и
показывает, что сохранение недоступно. Автоматического сброса или понижения версии нет.

Файл `.lock` координирует запись между экземплярами этой версии Oxide. Он остаётся
на диске, но блокировка ОС освобождается при закрытии handle или процесса.
Не удаляйте его при работающем плеере. Перед записью сравнивается загруженная
версия с сохранённой: устаревший экземпляр не перезапишет чужие изменения и
предложит перезапуск. Несохранённые изменения остаются активны только в этом окне;
автоматического объединения настроек/позиций нет. Сторонние редакторы и старые
сборки, игнорирующие `.lock`, не входят в эту гарантию согласования.

С `0.8.0-alpha.13` схема истории воспроизведения V2 хранит порядок давности
позиций и ограничивает его 1000 незавершёнными файлами. Дополнительно действует
бюджет 1 МиБ на данные путей позиций с учётом двух внутренних копий, 256 КиБ на
пути десяти недавних файлов и 128 КиБ на один путь. При заполнении удаляется
самая давно использованная позиция; медиафайлы не изменяются и не удаляются.
Открытие файла обновляет давность его позиции. V1 читается автоматически,
недавние записи защищаются при сокращении, а следующая запись создаёт V2 и
оставляет исходное состояние в `.bak`. Новые сборки не обещают сохранять более
1000 точек продолжения — это намеренная политика, а не ошибка записи.

Ошибки сохранения показываются в интерфейсе. Повторяющаяся ошибка фонового
сохранения истории сообщается один раз до успешной записи; при завершении она
также доступна в терминале. Ошибка записи позиции не мешает начать воспроизведение
заново. Чтение и запись одного файла ограничены 8 МиБ — превышение выдаёт ошибку,
а не усечение данных. Очистка истории из интерфейса остаётся отдельной задачей.

Аварийное завершение может оставить `.oxide-save-*.tmp`; при загрузке такие файлы
игнорируются, автоматического удаления чужих или старых временных файлов нет.
На Windows замена использует `MoveFileExW` с `WRITE_THROUGH`, на Unix — rename
и синхронизацию каталога. Unix-ветка ещё требует проверки на целевой ОС.
Защита от обрыва процесса не означает гарантии при отключении питания, поломке
накопителя или нестандартном поведении сетевой ФС. Нехватка места и отказ доступа
проверяются инъекцией ошибок; дополнительно проверен настоящий read-only файл
Windows. Реальный диск тестами не заполняется, пользовательская AppData не меняется.

## Завершение конвертации и приложения

### Доставка событий в интерфейс

С `0.8.0-alpha.11` плеер и конвертер имеют по 32 места для событий. Каждый
поток доставки передаёт в Slint не более одного пакета за раз (до 8 событий)
и ждёт подтверждения его обработки. Поэтому медленный интерфейс не превращает
ограниченную очередь в неограниченную очередь UI-callback. В простое потоки
спят на каналах, без периодического таймера; при закрытии окна отдельный сигнал
останавливает их даже при невыполненном callback и освобождает производителей.

Соседние отсчёты позиции и прогресса внутри пакета объединяются. Объединение
не пересекает смену файла, завершение или ошибку. События плеера и терминальные
события конвертации сохраняют порядок; при перегрузке их отправитель ждёт UI.
Промежуточный прогресс FFmpeg при заполнении очереди пропускается: он не должен
блокировать опрос отмены. Итоговый статус и финальный прогресс не отбрасываются.

Кнопка отмены передаёт сигнал непосредственно текущей задаче, минуя очереди.
Даже доставка `Started` проверяет отмену при ожидании свободного места. Процесс
FFmpeg останавливается, не ожидая, пока UI прочитает уведомление об отмене;
само уведомление может появиться позже. Следующая задача получает новый цикл отмены.

Для команд конвертера выделено 16 мест, для ожидающих задач — 32 (плюс одна
активная). Отправка из UI не ждёт свободного места: лишний запрос отклоняется
с понятным сообщением. Повторные запросы проверки FFmpeg объединяются.
Очистка очереди передаётся отдельным сигналом: отменяет ожидающие задачи и старые
запросы запуска, но сохраняет запросы, отправленные после очистки. Она не отменяет
текущую конвертацию. Выход тоже не зависит от свободного места в очереди команд.

С `0.8.0-alpha.12` очередь команд плеера ограничена 64 элементами. Соседние
абсолютные позиции, громкость, скорость, тема и запросы информации объединяются;
смена файла, относительные шаги и переключатели остаются границами порядка.
Отправка не ждёт места в очереди; при отказе UI получает сообщение через отдельный
ограниченный канал (1 место, один ожидающий callback). Очередь защищена коротким
mutex без вызовов mpv, файловых операций или ожидания свободного места внутри.

До готовности видеовывода команды открытия остаются в этой же очереди — отдельного
неограниченного списка больше нет. Для готовности OpenGL и HWND зарезервировано
по одному месту; повторные сигналы объединяются. Выход задаётся atomic-флагом,
проверяемым перед извлечением команды; накопленные команды при выходе не выполняются.
За проход обрабатывается до 8 команд и до 64 событий mpv, чтобы непрерывный поток
одного типа не вытеснял другой. Это не прерывает уже выполняющийся нативный вызов
или файловую операцию: ранее описанный предел ожидания завершения остаётся в силе.

С `0.8.0-alpha.14` ограничен и размер крупных данных. Путь в команде занимает
не более 128 КиБ. Автоматическая очередь папки хранит до 5000 файлов, 8 МиБ
путей и 4 МиБ подписей; явно открытый файл резервируется первым. Если остальное
не помещается, плеер сообщает число пропущенных файлов. Список дорожек ограничен
256 элементами, главы — 1000, отображаемые поля метаданных — 4 КиБ.

Lofty может прочитать суммарно до 16 МиБ метаданных и выделить до 8 МиБ на один
tag item. Сжатая обложка допускается до 8 МиБ; декодер ограничен 4096×4096 и
64 МиБ, а передаваемое в UI изображение уменьшается максимум до 1024×1024 RGBA.
Сохранённые переназначения ограничены 64 записями и 256 байтами на код клавиши.
Эти пределы предотвращают неограниченное накопление, но ещё не являются замером
RSS всего приложения: профилирование с реальными медиа остаётся обязательным.

### Процессы и завершение

Обнаружение FFmpeg ограничено тремя секундами и 64 КиБ суммарного вывода на
каждый проверяемый путь. Выход из приложения прерывает проверку. У самой
конвертации общего тайм-аута нет: отмена работает и при отсутствии прогресса.
Вывод читается без отдельных reader-потоков; размер строки ограничен 8 КиБ,
накопленная диагностика — 32 КиБ. Задача владеет процессом и временным результатом,
dispatcher — её потоком. Ошибка или panic освобождает очередь для следующей задачи.

На Windows FFmpeg включается в Job Object с остановкой при закрытии handle:
отмена и выход останавливают его и присоединённых потомков. После запроса
остановки ожидание прямого дочернего процесса ограничено двумя секундами.
Присоединение выполняется сразу после `spawn`; это не sandbox и не гарантия
перехвата потомков, успевших появиться до присоединения.

После завершения UI приложение ждёт фоновые потоки до пяти секунд. Если вызов
ОС/libmpv остался заблокирован, процесс выходит с ошибкой вместо бесконечного
ожидания. При таком аварийном выходе сохранение последних позиций и удаление
временного файла не гарантируются. Проверка реальной конвертации и выхода через
интерфейс выполняется вручную. Unix-ветка управления группой процессов пока не
проверена на целевой ОС; переносимость остаётся отдельной задачей.

### Безопасное сохранение результата

Конвертация использует отдельную папку `.oxide-part-*` рядом с будущим результатом.
Папка резервируется эксклюзивно; существующие папки и их содержимое не используются.
При обычном завершении, отмене или ошибке удаляются только собственный временный
файл и пустая папка. Аварийное завершение процесса может оставить эту папку на диске.

После завершения FFmpeg файл синхронизируется и публикуется без перезаписи занятого
имени. Если другой процесс успел создать файл с таким же именем, его содержимое
остаётся прежним, задача получает ошибку вместо ложного успеха. Нужно выбрать
другое имя и повторить конвертацию; временный результат при ошибке удаляется.

На Windows используется перенос без `REPLACE_EXISTING` и без копирования между
томами. На Unix — создание жёсткой ссылки с последующим удалением временной;
эта ветка ещё требует проверки на целевой ОС. Если файловая система не поддерживает
операцию, конвертация завершается ошибкой: запасного пути через перезапись или
частичное копирование нет. Это не обещание сохранности при отключении питания,
сбое накопителя или вмешательстве в рабочую папку сторонней программы.

## Основные клавиши

| Клавиша | Действие |
|---|---|
| `Ctrl+K` | Открыть палитру команд |
| `Ctrl+O` | Открыть файл |
| `Ctrl+Shift+O` | Открыть папку |
| `Ctrl+L` | Открыть плейлист |
| `Space` или `K` | Play / pause |
| `J` / `L` | Назад / вперёд на 10 секунд |
| `←` / `→` | Назад / вперёд на 5 секунд |
| `↑` / `↓` | Изменить громкость |
| `M` | Mute |
| `R` | Повтор текущего файла |
| `S` | Остановить воспроизведение |
| `F` | Полноэкранный режим |
| Двойной клик по видео | Полноэкранный режим |
| `N` / `P` | Следующее / предыдущее видео |
| `I` | Информация о медиа |
| `H` | Справка по клавишам |
| `O` | Открыть файл |

Буквенные сочетания привязаны к физическим клавишам и работают одинаково в
английской, русской и других раскладках. Откройте «Команды и горячие клавиши»
кнопкой клавиатуры или `Ctrl+K`. Первый клик по другой строке выбирает команду;
повторный клик по выбранной строке (или `Enter` в поиске) запускает её.
Клик по полю горячей клавиши или `F2` раскрывает редактор под выбранной строкой:
поле записи с приглашением «Нажмите сочетание на клавиатуре» и движущейся
пунктирной обводкой. Кнопка «Сохранить» появляется внутри поля справа только
после ввода допустимого сочетания, отличающегося от текущего.
Текущее назначение и восстановление исходного сочетания расположены в шапке
двумя колонками: подпись сверху, значение в компактной плашке по центру ниже. Вся колонка восстановления
доступна для нажатия. Шапка и редактор объединены общим внешним контуром.
Во время редактирования текущее сочетание показано компактной подписью в шапке;
акцентный фон выделяет только шапку, а «Сохранить» получает акцент после допустимого ввода.
Соседние строки плавно сдвигаются, а список прокручивается так, чтобы редактор
оставался видимым. Пока новое сочетание не введено, повторный клик по раскрытой
строке закрывает редактор, клик по другой строке выбирает её, а клик по её
сочетанию начинает его запись. При попытке перейти с несохранённым вводом
редактор остаётся открыт: предупреждение временно заменяет сочетание в поле,
дважды плавно пульсирует и исчезает, возвращая введённое значение. Только пока
предупреждение отображается, следующий клик по другой команде отменяет ввод и
выполняет переход; клик по текущей команде оставляет редактор открытым. Когда
предупреждение исчезло или ввод изменился, подтверждение сбрасывается: следующий
клик снова сначала покажет предупреждение.
Пока предупреждение видно, кнопка «Сохранить» скрыта. При уменьшении движения
предупреждение показывается без пульсации и затем скрывается.
Клик за пределами окна при несохранённых изменениях запускает закрытие через три
секунды. Основное содержимое размывается, по центру появляется предупреждение
с отсчётом рядом с «Закрыть меню» и плавно убывающей полоской. Размытие использует
однократный снимок модального окна в памяти; файл изображения не создаётся.
«Закрыть меню» отменяет черновик и закрывает меню сразу;
«Отменить закрытие» или `Esc` останавливает отсчёт и возвращает к тому же черновику.
Повторный клик снаружи не перезапускает таймер. Отсчёт идёт по прошедшему времени
и продолжается при переключении фокуса на другое приложение. Без изменений
клик снаружи закрывает окно сразу, даже если редактор открыт.
В списке выбранное поле отмечено статичной акцентной рамкой. Marching Ants
работает только в поле записи во время ожидания ввода; при включённом
уменьшении движения обводка остаётся неподвижной. Ввод текущего назначения
не считается изменением и не требует сохранения.
Проверьте сочетание и нажмите «Сохранить»;
`Esc` отменяет ввод и оставляет прежнее назначение. Для занятого сочетания вместо
«Сохранить» доступно явное действие «Переназначить». До нажатия поле предупреждает,
какая команда останется без горячих клавиш. После подтверждения её назначения
(включая альтернативные клавиши) очищаются, а выбранная команда получает сочетание.
Оба изменения сохраняются между запусками; пустое назначение не заменяется
стандартным при загрузке. Простое введение занятого сочетания ничего не меняет.
`Tab` завершает запись и переводит фокус к кнопкам.
Свободное сочетание подсвечивается зелёным, занятое — красным. Пояснение конфликта
показывает занятое значение и последствия переназначения прямо в поле ввода,
плавно пульсирует, затем остаётся рядом с кнопкой. Новое значение можно ввести сразу, не дожидаясь
окончания анимации. Название редактируемой команды и ошибка внизу не дублируются;
там остаётся выровненное по центру короткое пояснение и отдельные обозначения доступных клавиш:
`Enter`, `F2`, `Esc` при выборе команды; `Tab`, `Esc` при редактировании.
Пока поле ввода в фокусе, каждое новое
сочетание заменяет предыдущее — и свободное, и занятое — без предварительного клика.
Удержание клавиши не повторяет запись; `Tab` переводит фокус к действиям и
приостанавливает такой ввод, чтобы `Enter`/`Space` могли активировать кнопку.
Чтобы вернуться к вводу после кнопок, сфокусируйте поле кликом или через `Tab`.
Клик по полю сохраняет черновик, пока не нажато новое сочетание.
Действие «Восстановить …» с
исходным сочетанием в подписи появляется в шапке, когда сохранённое назначение или
введённый вариант отличается от исходного. Оно подставляет исходное сочетание;
сброс применяется после нажатия «Сохранить»;
общий сброс требует отдельного подтверждения. Изменения сохраняются между запусками.
