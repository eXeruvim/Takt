# Поддержка Oxide 1.0

[English](SUPPORT.en.md) · **Русский**

Этот документ помогает отличить известное ограничение от ошибки и собрать
достаточно сведений для воспроизводимого отчёта. Не прикладывайте сам медиафайл,
его полный путь, историю воспроизведения или дамп памяти, если этого отдельно не
попросили и вы не проверили содержимое.

## Известные ограничения Windows 1.0

- Поддерживается Windows 10/11 x86-64. Версия для Linux запланирована после 1.0.
  ARM64 и macOS сейчас не входят в план поддерживаемых платформ.
- В maximized/fullscreen системный DWM не гарантирует живую прозрачность окна.
  Oxide использует непрозрачный визуально согласованный fallback, а не захват
  рабочего стола. Это исключает лишнюю нагрузку, задержку и захват приватного
  или DRM-содержимого.
- Аппаратное декодирование зависит от видеокарты, драйвера и формата. При
  артефактах отключите его в разделе «Видео»: программное декодирование является
  корректным fallback. Поддержка формата определяется поставляемой libmpv/FFmpeg
  сборкой и зафиксирована в `CODEC_MATRIX.md`.
- Медленный или изношенный HDD может давать паузу при первом открытии, seek или
  переходе к следующему большому файлу. Oxide использует ограниченный read-ahead,
  но не читает целый локальный файл в память и не скрывает реальный I/O stall.
- Конвертер требует отдельно установленный пользователем `ffmpeg.exe`. Он не
  загружается автоматически и не входит в Oxide 1.0; воспроизведение работает
  без него.
- Пакеты пока не имеют коммерческой Authenticode-подписи, поэтому SmartScreen
  может показать предупреждение для первого малораспространённого релиза.
  Проверяйте SHA-256 с release page. Встроенное обновление независимо проверяет
  Ed25519-подпись проекта и SHA-256 до запуска пакета.
- Portable-обновлению нужен доступ на запись к каталогу, куда распакован Oxide.
  При недостатке прав или места текущая версия сохраняется и запускается снова;
  причина показывается при следующем старте.

## Перед отчётом

1. Повторите ошибку на последней доступной версии и запишите точные действия.
2. Проверьте, повторяется ли она после перезапуска Oxide.
3. Для видеоартефакта сравните аппаратное декодирование «вкл.» и «выкл.».
4. Для медленного файла укажите тип носителя (SSD/HDD/сетевой), но не полный путь.
5. Для конвертера приложите последнюю строку журнала и вывод `ffmpeg -version`,
   не прикладывая исходный медиафайл.

## Безопасная диагностика

В PowerShell, находясь рядом с `oxide.exe`, выполните:

```powershell
(& .\oxide.exe --build-info 2>&1 | Out-String).Trim()
(& .\oxide.exe --native-info 2>&1 | Out-String).Trim()
```

Первая команда печатает версию пакета, commit и состояние исходной сборки;
вторая — версии mpv, FFmpeg и libass из реально загруженной DLL. Обе команды
работают без открытия UI и медиа. В выводе нет истории и пользовательских путей.

Для разработческой сборки дополнительно выполните:

```powershell
cargo test --locked --all-targets
cargo clippy --locked --all-targets -- -D warnings
```

Если проблема связана с установкой или обновлением, укажите installer/portable,
этап (проверка, загрузка, применение, первый запуск или откат) и текст сообщения.
Последняя локальная ошибка helper хранится во временном каталоге Windows только
до следующего запуска Oxide, после показа удаляется.

```text
Oxide: <вывод --build-info>
Native runtime: <вывод --native-info>
Windows: <10/11, версия>, масштаб интерфейса: <%>
Видеокарта и драйвер: <если относится к видео>
Пакет: <installer/portable>
Носитель: <SSD/HDD/сетевой каталог>

Шаги:
1. …
2. …
3. …

Ожидалось: …
Получилось: …
Повторяемость: <всегда/иногда, примерно N из M>
Аппаратное декодирование: <вкл./выкл./оба>
```

Скриншот или короткая запись экрана полезны для визуальной ошибки. Перед
публикацией закройте имена личных файлов, уведомления и другие приватные данные.
