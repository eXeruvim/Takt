# Архитектура Oxide

## Границы системы

Oxide разделён на UI-поток и поток проигрывателя. UI не вызывает libmpv напрямую:
команды и события передаются через каналы `crossbeam-channel`.

```text
Slint UI -> ipc::Command -> player::mpv -> libmpv
Slint UI <- ipc::Event   <- player::mpv <- libmpv events
```

Такое разделение не позволяет медленным операциям декодирования или файловой
системы блокировать event loop интерфейса.

## Модули

- `src/ipc.rs` — контракт между UI и проигрывателем;
- `src/player/mpv.rs` — жизненный цикл libmpv, команды и события;
- `src/player/playlist.rs` — обнаружение и сортировка видео и аудио в папке;
- `src/player/media_info.rs` — чтение свойств медиа;
- `src/player/shortcuts.rs` — будущая модель переназначаемых клавиш;
- `src/render/` — интеграция поверхности видео с окном приложения;
- `src/ui/ui_logic.rs` — связывание Slint callbacks с IPC;
- `ui/` — декларативные компоненты Slint.

## Правила развития

1. Ошибка отдельной команды не должна завершать поток проигрывателя.
2. UI получает состояние через события, а не опрашивает libmpv.
3. Работа с плейлистом и метаданными тестируется без запуска окна.
4. Цвета, размеры и состояния UI задаются семантическими токенами.
5. Платформенный Win32-код остаётся внутри `render` и `cfg(windows)`.
6. FFmpeg запускается отдельным процессом и никогда не блокирует UI или mpv.

## Решение по выводу видео для Windows 1.0

Для первой Windows-версии используется синхронизируемый дочерний HWND, передаваемый
libmpv через свойство `wid`. Поверхность учитывает размер окна и DPI, не получает
клавиатурный фокус, поддерживает fullscreen и освобождает место для панелей Slint.

Прямой OpenGL render API пока не используется: текущий `libmpv-rs` объявляет модуль
`render`, но не предоставляет готовой безопасной реализации. Собственная обвязка
`libmpv-sys` потребовала бы ручного управления OpenGL-контекстом и состоянием
рендерера Slint. Такое усложнение не оправдано, пока Windows HWND обеспечивает
стабильное воспроизведение. Render API остаётся кандидатом для кроссплатформенной
версии или UI с произвольными overlay непосредственно поверх кадра.
