# Архитектура Oxide

## Границы системы

Oxide разделён на UI-поток и поток проигрывателя. Управляющие вызовы libmpv
изолированы в потоке проигрывателя; команды и события передаются через ограниченные
каналы. Единственное намеренное исключение — render API: Slint вызывает его внутри
rendering notifier, пока OpenGL-контекст окна активен.

```text
Slint UI -> ipc::Command -> player::mpv -> libmpv
Slint UI <- ipc::Event   <- player::mpv <- libmpv events
player::mpv -> one-shot MpvRenderSource -> ui::video_output

player::mpv -> bounded session snapshot -> storage writer
player::mpv -> latest metadata request -> cancellable metadata worker
player::mpv -> latest playlist request -> cancellable directory scanner

Slint UI -> converter::ConverterCommand -> converter -> FFmpeg process
Slint UI <- converter::ConverterEvent   <- converter <- FFmpeg progress
```

Такое разделение не позволяет медленным операциям декодирования или файловой
системы блокировать event loop интерфейса.

## Модули

- `src/ipc.rs` — продуктовые команды и события между UI и проигрывателем;
- `src/player/mpv.rs` — жизненный цикл libmpv, команды и события;
- `src/player/mpv_adapter.rs` — создание и начальная настройка libmpv,
  регистрация наблюдаемых свойств и платформенные значения параметров;
- `src/player/playback_diagnostics.rs` — опциональные счётчики libmpv,
  включаемые переменной окружения, и владение диагностическим отчётом;
- `src/player/playback_state.rs` — явные переходы ожидания позиции продолжения
  и подавления повторной записи очищенной истории;
- `src/player/background_jobs.rs` — единый владелец фоновых задач проигрывателя:
  выдаёт результаты после приоритетной обработки команд и отбрасывает ответы с
  устаревшими generation/path до изменения состояния или отправки события в UI;
- `src/player/latest_worker.rs` — общий ограниченный механизм фоновых задач:
  одна активная и одна заменяемая заявка, кооперативная отмена, один готовый
  результат и обязательное присоединение потока при shutdown;
- `src/player/playlist.rs` — обнаружение и сортировка видео и аудио в папке;
- `src/player/playlist_worker.rs` — один отменяемый latest-request worker
  формирования ограниченной очереди без блокировки команд libmpv;
- `src/player/media_info.rs` — чтение свойств медиа;
- `src/player/metadata_worker.rs` — один ограниченный worker чтения аудиотегов
  и обложки с отменой текущей работы и заменой ожидающей заявки;
- `src/player/session_store.rs` — модель истории/позиций и один ограниченный
  фоновый writer; очистка и shutdown используют подтверждённый flush;
- `src/player/shortcuts.rs` — типизированные действия, физические сочетания,
  конфликты, черновик редактирования и сохранение пользовательских назначений;
- `src/converter.rs` и `src/converter/` — координация конвертации с отдельными
  владельцами обнаружения FFmpeg, профилей и аргументов кодирования, очереди,
  процесса, публикации результата и ограниченного разбора progress/diagnostic
  потоков;
- `src/render/` — интеграция поверхности видео с окном приложения;
- `src/ui/ui_logic.rs` — связывание Slint callbacks с IPC;
- `src/ui/conversion_controller.rs` — UI-состояние конвертера: выбор входа и
  результата, пресеты, отправка задач, история и применение событий FFmpeg;
- `src/ui/settings_controller.rs` — применение и сохранение пользовательских
  параметров темы, акцента, воспроизведения и аппаратного декодирования;
- `src/ui/video_output.rs` — Windows-жизненный цикл встроенного OpenGL-вывода,
  HWND fallback, render notifier и handshake готовности видео с player thread;
- `src/ui/player_event_controller.rs` — применение ограниченных пакетов событий
  проигрывателя к Slint-модели, включая переходы медиа, таймлайн и метаданные;
- `src/ui/player_command_controller.rs` — перевод файловых, транспортных,
  аудио- и playlist-действий Slint в типизированные команды player thread;
- `src/ui/shortcut_controller.rs` — UI-состояние Command Palette и редактора
  сочетаний: явные состояния активного редактирования и feedback сохранения,
  capture физических клавиш, dispatch, модель поиска, сохранение и согласованный
  сброс настроек;
- `src/ui/window_event_controller.rs` — маршрутизация нативных событий окна:
  focus и системная тема, move/resize, drag-and-drop, жесты Inspector, модальные
  клавиши и передача физических сочетаний контроллеру shortcuts;
- `src/ui/drawer_controller.rs` — переход между сторонами Inspector через закрытие,
  переключение вкладок общей панели на месте и раздельная синхронизация
  Windows-видеослоя и плавного аудиомакета; межсторонний переход использует
  отдельный короткий motion-профиль без ускорения обычного закрытия;
- `src/ui/command_catalog.rs` — неизменяемые описания команд и независимый от
  Slint поиск по локализованным названиям, описаниям и aliases;
- `src/ui/presentation.rs` — чистое форматирование времени, размеров и медиа-
  свойств для UI без зависимости от окна Slint;
- `src/ui/window_placement.rs` — восстановление normal bounds на доступном
  мониторе, запись положения и объединение нативных move/resize-событий без
  устаревшей геометрии;
- `src/ui/window_interaction.rs` — HWND-доступ и жизненный цикл ручного drag с
  Win32 mouse capture, включая восстановление maximized-окна под курсором;
- `src/ui/window_modes.rs` — единый владелец состояния fullscreen и picture-in-
  picture, включая сохранение и восстановление прежней геометрии;
- `src/ui/windows_theme.rs` — изолированное чтение системной темы Windows;
- `ui/` — декларативные компоненты Slint.

## Правила развития

1. Ошибка отдельной команды не должна завершать поток проигрывателя.
2. UI получает состояние через события, а не опрашивает libmpv.
3. Работа с плейлистом и метаданными тестируется без запуска окна.
4. Цвета, размеры и состояния UI задаются семантическими токенами.
5. Платформенный Win32-код остаётся в модулях `render`/`ui` под `cfg(windows)` и
   не проникает в модель проигрывателя.
6. FFmpeg запускается отдельным процессом и никогда не блокирует UI или mpv.

## Решение по выводу видео для Windows 1.0

Основной backend использует `libmpv` render API и рисует кадр в текущий OpenGL-
framebuffer FemtoVG перед Slint-сценой. Благодаря общей композиции title chrome,
control deck, Inspector и modal-поверхности могут находиться непосредственно поверх
видео, не изменяя геометрию video target при появлении или автоскрытии.

`libmpv-rs` не предоставляет готовую реализацию своего пустого `render`-модуля,
поэтому минимальная безопасная обвязка `libmpv-sys` изолирована в
`src/render/mpv_opengl.rs`. Она создаёт и освобождает render context на UI/render-
потоке, получает OpenGL symbols через FemtoVG и переводит update callback mpv в
запрос кадра Slint. Перед началом playback UI подтверждает готовность render context,
а после создания контекста, каждого кадра и освобождения восстанавливаются
framebuffer, viewport, scissor, blending, clear color и dithering, которые libmpv
явно исключает из своей гарантии сброса состояния.

## Контракты FFI и владения

- `MpvOpenGlRenderer` намеренно не реализует `Send`/`Sync`. Создание, render,
  `report_swap` и уничтожение допустимы только из rendering notifier Slint при
  активном исходном OpenGL-контексте; этот внешний инвариант отражён в `unsafe` API.
- Источник render API удерживает `Arc<Mpv>` дольше render context. Update callback
  получает стабильный адрес обычного `Box<UpdateTarget>`; `Drop` сначала снимает
  callback, затем освобождает context, и только после этого освобождается Box.
- Ни одна Rust-паника из загрузчика GL symbols или update callback не пересекает
  границу C ABI. Callback только объединяет запросы перерисовки и не вызывает mpv.
- `VideoHost` хранит ненулевой HWND, принадлежит потоку окна и также намеренно
  не является `Send`/`Sync`. Его `Drop` уничтожает только ещё существующий дочерний
  HWND на том же UI/render-потоке.
- Полноэкранный режим передан единому borderless-fullscreen механизму Slint/winit.
  Он владеет переходом Windows, скрытием taskbar и восстановлением предыдущего
  maximized/windowed placement. UI меняет своё fullscreen-состояние только после
  передачи запроса оконному backend; параллельная ручная цепочка изменения
  placement/topmost не используется. На Windows перед нативным переходом через
  winit отключаются decorations, затем синхронизируется fullscreen-свойство Slint.
  Одного порядка вызовов оказалось недостаточно (ручная проверка 24.09.2026).
  `native_frame` устанавливает на HWND статический subclass в `RenderingSetup`:
  Slint 1.17.1/winit сначала рисует первый кадр скрытого окна и лишь затем
  вызывает `set_visible(true)`. Отложенный callback event loop для этого слишком
  поздний: между показом окна и установкой subclass мелькает системная шапка.
  `app.show()` до запуска цикла только ставит создание окна в очередь; получать
  HWND сразу после него нельзя. Ошибка установки завершает цикл и
  возвращается после штатной очистки. Subclass обеспечивает собственный расчёт
  client area для `WM_NCCALCSIZE`, подавление `WM_NCPAINT` и двух legacy UAH draw
  сообщений. `WM_NCACTIVATE` передаётся winit с `lParam=-1`: учёт фокуса сохраняется,
  стандартный заголовок не перерисовывается. Maximized ограничивается рабочей
  областью целевого монитора, fullscreen сохраняет всю область монитора. При
  выходе из fullscreen winit восстанавливает ранее сохранённый `WINDOWPLACEMENT`;
  для безрамочного окна предложенная им maximized-геометрия дополнительно
  нормализуется в `WM_WINDOWPOSCHANGING`, до её применения Windows. Это штатная
  точка расширения Win32 и не требует таймера либо повторного `SetWindowPos`
  после перехода.
  Одного подавления рисования оказалось недостаточно. При установке удаляются
  `WS_CAPTION` (включая BORDER/DLGFRAME) и декоративные extended-edge стили.
  `WM_STYLECHANGING` фильтрует те же биты при последующих записях winit, до их
  применения Windows. Остальные стили, включая `WS_THICKFRAME`, видимость,
  minimize/maximize, taskbar и прозрачность, остаются под управлением backend.
  Название/иконка передаются штатно. Неудачный обход с кратковременным снятием
  `WS_VISIBLE` удалён. Политика проверяется на скрытом HWND с повторными записями
  стилей и передачей сообщений активации; визуальные эффекты и snap требуют
  ручной приёмки.
  `WS_EX_WINDOWEDGE` не фильтруется: проверка реального HWND показала, что user32
  автоматически сохраняет его при `WS_THICKFRAME`. Независимые CLIENTEDGE,
  STATICEDGE и DLGMODALFRAME убираются; размером окна по-прежнему управляет winit.
  При оконном live-resize `WM_NCCALCSIZE` возвращает `WVR_VALIDRECTS`: точное
  пересечение старой и новой client area копируется в те же экранные координаты.
  Поэтому левая/верхняя границы не должны сдвигать уже показанный кадр, пока Slint
  готовит поверхность нового размера. При maximized/fullscreen сохранение области
  отключено; периодический запрос кадра в modal resize-loop остаётся независимым.
  Регистрация хранит только целевой fullscreen-флаг, а не указатель на Rust;
  удаляется на `WM_NCDESTROY`. Установка разрешена только в потоке владельца окна.
  Для Windows/MSVC `build.rs` встраивает activation manifest с зависимостью
  `Microsoft.Windows.Common-Controls` v6: `GetWindowSubclass` отсутствует среди
  именованных экспортов legacy `System32/comctl32.dll`. Без манифеста процесс
  завершается до main с `STATUS_ENTRYPOINT_NOT_FOUND`. Проверка загрузки готового
  приложения без UI: `target/debug/oxide.exe --build-info` (одной линковки мало).
  Фильтрация `WS_CAPTION` централизована в `native_frame`; placement остаётся у winit.
  `WS_THICKFRAME` остаётся для resize/snap, а позицию, размер, taskbar и z-order
  эта защита не меняет: единственной видимой шапкой остаётся chrome Oxide.

Остаточные внешние допущения проверяются на релизном native-наборе: Slint должен
сохранять исходный GL-контекст активным до `RenderingTeardown`, а конкретная сборка
libmpv и драйвер должны соблюдать заявленный render API. OpenGL debug callback,
который mpv тоже относит к исключённому состоянию, пока не сохраняется: FemtoVG его
не устанавливает, а универсальная поддержка потребовала бы GL 4.3. Это явно
проверяется ручным smoke-тестом и остаётся предметом повторной проверки при смене
renderer/backend.

Старый дочерний HWND пока присутствует в коде как аварийный Windows-путь, но не
считается принятым release-backend. Ручная проверка показала, что `wid` + `vo=gpu`
нарушает прозрачную ambient-композицию, перекрывает Slint-экраны и панели, мерцает
при переходах и нестабилен в borderless fullscreen. До 1.0 автоматический переход
на этот путь должен быть удалён либо заменён совместимым способом вывода; численные
результаты такого fallback нельзя выдавать за целевую оптимизацию Oxide.
